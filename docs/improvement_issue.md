# 報告内容整理機能の大幅改善

## 概要

青梅市向け報告内容整理機能を大幅に改善し、より柔軟で充実した通報受付システムを実現しました。

## 改善内容

### 1. 通報カテゴリの充実と柔軟化

#### 野生動物被害（wildlife_damage）
- **対象動物リストを拡張**: イノシシ、サル、カラス、シカに加え、ハクビシン、タヌキ、クマ、外来種など地域固有の動物も登録
- **被害タイプの細分化**: 農作物被害、住宅侵入、人的被害、交通事故などでタグ付け
- **危険度判定**: メッセージから「威嚇」「怪我」「車と衝突」などのキーワードを抽出し、緊急度を算出

#### インフラ損傷（infrastructure_damage）
- **インフラ種別**: 道路（陥没・亀裂・段差）、橋梁／高架（腐食・ガードレール欠損）、照明／信号（街灯不点灯・信号故障）、水道／下水（破裂・詰まり）、公共施設（公園遊具、公共トイレ、壁面剥離）など
- **危険度判定**: 通行止めが必要か暫定対応でよいか判定するため、「車が通れない」「怪我人が出た」といった表現を抽出

#### ごみ問題（garbage_issue）
- **ごみの種類**: 不法投棄（粗大ごみ・家電）、ポイ捨て（軽微な散乱）、集積所問題（破損・カラス被害による散乱・回収漏れ）
- **発生頻度の記録**: 同じ場所に繰り返し通報がある場合、慢性的な問題としてフラグを立て、対応方針を検討

#### その他（other）
- **包括的なサブカテゴリ**: 騒音問題、異臭・悪臭、迷惑駐車、違法広告・看板、危険物や薬物関連、野良犬・野良猫、落書き・器物損壊、不審者情報、照明や光害、衛生害虫の異常発生、通信設備のトラブル、水質・土壌汚染、公共交通機関のトラブル、防犯灯や監視カメラの不具合、産業・商業活動への苦情、交通信号・標識の異常、人権・迷惑行為など
- **未知の事例**: 新たなパターンが確認された場合はログに蓄積し、カテゴリ追加を検討

#### マルチラベル分類とサブカテゴリ
- 一つの通報が複数のカテゴリに関係する場合（例：サルがごみを散乱させ道路を塞ぐ）はマルチラベルで処理
- 各大カテゴリの下にサブカテゴリを設けることで、担当部署が迅速に対応できるようにする

### 2. 情報抽出スロットの拡張と精度向上

#### 新規スロット
- `attachments`: 写真・動画・音声など、通報を補強する添付ファイル（画像解析や音声認識を将来的に組み込むための拡張性を確保）
- `priority`: 緊急度（抽出キーワードに基づいて自動判定し、担当部署へ通知）
- `garbage_type`: ごみの種類
- `recurrence`: 繰り返し発生フラグ
- `traffic_impact`: 通行への影響
- `injury_report`: 怪我人の有無
- `volume`: ごみの量
- `subcategory`: サブカテゴリ

#### 抽出精度向上
- NERモデルと正規表現の併用
- 過去履歴との照合（将来的に実装）
- 地図選択・位置共有機能と連携し、誤入力を減らす（将来的に実装）

### 3. 不足情報検出とスマートな質問生成

#### 優先順位のダイナミック設定
- デフォルトは `location` → `time` → `species` → `damage_type` → `details` → `attachments`
- 内容の緊急度や会話文脈に応じて順序を調整
- 危険度が高い案件は先に確認

#### 質問生成のパーソナライズ
- ユーザーの回答傾向を学習し、選択肢式・入力例付き・自由記述など最適な形式を提示（将来的に実装）
- 共感やねぎらいの言葉を挟み、機械的な印象を軽減

#### 自動補完と確認プロセス
- 推測できるスロットは自動で仮値を提示し、「こちらで間違いないですか？」と確認
- 確信度が低い場合は明示的な質問を生成し、誤解を防ぐ

### 4. 対話管理とユーザー応答処理

#### LangGraphベースのワークフロー拡張

**新規ノード**:
- **感情検知ノード**: 返信速度や表現から緊張度・緊急度を推定し、応答トーンや優先度を調整
- **要約確認ノード**: 全スロットが埋まった際、まとめ情報を提示してユーザー確認
- **フォローアップノード**: 通報受付後は受付番号や処理状況の概要を返信し、ユーザーの安心感を高める

**状態遷移の柔軟化**:
- 特定のスロットが埋まったら、関連する質問を追加したり次のステップへスキップしたりする
- ユーザー応答の処理強化（矛盾や不足情報があれば優しく確認）
- 一定時間応答がない場合はリマインダー送付やオペレーター接続案内（将来的に実装）

### 5. 技術スタックとアーキテクチャ

#### 実装済み
- **言語・基盤**: Python 3.11+
- **ワークフロー管理**: LangGraph
- **APIレイヤー**: FastAPI

#### 将来的な拡張
- **非同期通信**: asyncio を活用し、応答を高速化
- **データストア**: PostgreSQL / MongoDB（通報データ、ユーザー履歴、カテゴリ辞書を永続化）
- **メッセージング**: RabbitMQやRedis Streams（通知処理やバックグラウンドタスクを非同期で処理）
- **セキュリティ**: HTTPS通信、データの暗号化、権限管理、ログ監査
- **モデルと辞書管理**: 日本語BERTなどのモデルファイルを安全に運用、地域特有の用語を管理する辞書を定期的に更新
